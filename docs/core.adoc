= Core
:toc:
:toclevels: 2

`core` is the pure domain module: the `Op` effect, the phase machinery, the command handlers, the three aggregates (user, survey, video), the repository traits and the i18n key schema. It has no effect type, no database and no HTTP, and its sources are compiled twice — as `core` for the JVM and as `core-js` for Scala.js.

== Module shape

Both modules are declared in `build.mill` and share one source tree:

[source,scala]
----
object core extends BaseModule with CoreDepsJVM:
  object test extends ScalaTests with TestModule.Utest …

object `core-js` extends BaseJSModule with CoreDepsJS:
  def sources = core.sources
----

[cols="1,3"]
|===
| | Dependencies

| `core`
| cats-core, circe (core/generic/parser), babel (`io.taig::babel-core`, `babel-generic`, `babel-circe`)

| `core-js`
| the same, plus `io.github.cquiroz::scala-java-time` for the `java.time` types the domain uses
|===

Everything in the tree is JS-visible, because `core-js` compiles the same files: the browser reuses `AnswerValue`, `QuestionToAnswer`, `QuestionType`, the rule enums, `IsoDate`, `Phase` and the circe codecs, so the portal renders and pre-validates forms against the domain's own types instead of a parallel copy. The repository traits are abstract in `F[_]`; the implementations are JVM-only and live in xref:platform.adoc[Platform].

== Op[Evt, E, A]

`core/src/whitelabel/captal/core/Op.scala` is the domain's only effect. It is an opaque type over a writer transformer:

[source,scala]
----
opaque type Op[Evt, E, A] =
  WriterT[[X] =>> Either[NonEmptyChain[E], X], Chain[Evt], A]
----

So the underlying value is `Either[NonEmptyChain[E], (Chain[Evt], A)]`:

* events accumulate in a `Chain`, appended in O(1);
* events exist only on the success side — a failed `Op` carries errors and no events;
* `flatMap` is fail-fast; `parMapN` / `parTupled` / `parTraverse` accumulate errors into the `NonEmptyChain`.

=== Operations

[cols="2,3"]
|===
| Operation | Meaning

| `pure(a)`
| success, no events

| `emit(event, a)` / `emit(event)`
| success carrying one event (the second form yields `Unit`)

| `emitAll(events, a)`
| success carrying a `Seq` of events

| `fail(err)` / `failAll(errs)`
| failure with one error, or with a `NonEmptyChain` of them

| `failIf(cond, err)` / `failUnless(cond, err)`
| guard clauses; the error is by-name

| `fromEither(either)` / `fromOption(opt, ifNone)`
| lift an existing result

| `run(op)`
| `Either[NonEmptyChain[E], (List[Evt], A)]` — the only way out

| `convertEvent[Evt2]` / `convertError[E2]`
| widen an aggregate-local `Op` to the application-level one, through a `Conversion`
|===

Instances: `Monad[[A] =>> Op[Evt, E, A]]` and `Parallel[[A] =>> Op[Evt, E, A]]`, both in the companion. The `Parallel` instance is what makes rule validation accumulate rather than stop at the first broken rule.

=== Widening

Aggregate operations are typed in their own event and error ADTs (`Op[user.Event, user.Error, A]`, and likewise for `survey` and `video`). `core/src/whitelabel/captal/core/application/conversions.scala` supplies the six `Conversion` instances that lift them into `application.Event` / `application.Error`, and handlers apply them with `.convertEvent.convertError`:

[source,scala]
----
user.finish(cmd.occurredAt).convertEvent.convertError.void
----

`convertError` collapses a whole `NonEmptyChain[user.Error]` into a single `Error.User(errors)`, so the application-level chain holds one element per aggregate that failed.

=== Consumption

`core/src/whitelabel/captal/core/application/Flow.scala` is the one consumer:

[source,scala]
----
def execute(command: C): F[R] =
  for
    opResult <- handler.handle(command)
    result   <- MonadThrow[F].fromEither(Op.run(opResult).left.map(HandlerError(_)))
    (events, value) = result
    _ <- eventHandler.handle(events)
  yield value
----

Errors surface as `Flow.HandlerError(errors: NonEmptyChain[Error])`, a `java.lang.Exception`; the API translates it to `ApiError` (see xref:messages.adoc[Messages]). Events reach the handler chain only after `Op.run` succeeded, which is what makes "no events on failure" an end-to-end property rather than a convention.

== Phases and flow machinery

=== Phase

`application/phase.scala` holds the portal's nine phases plus their database spelling. `sessions.phase` stores the string.

[cols="2,2,3"]
|===
| `Phase` | DB string | What the guest is doing

| `Welcome` | `welcome` | landed on the portal, no survey assigned yet; its device accepted the terms of service in force
| `WelcomeNeedsToS` | `welcome_needs_tos` | the welcome, with the terms of service still to accept: never accepted, an older version accepted, or a request with neither the session nor the user cookie
| `IdentificationQuestion` | `identification_question` | answering email / profiling / location questions
| `AdvertiserVideo` | `advertiser_video` | watching the assigned video
| `AdvertiserVideoSurvey` | `advertiser_video_survey` | answering the question that follows the video
| `AdvertiserQuestion` | `advertiser_question` | declared, not used by any transition in `api.Phases`
| `Ready` | `ready` | flow complete, access not granted yet
| `Recovered` | `recovered` | left through an error, access not granted yet; unlike `Ready`, with no user required
| `Authorized` | `authorized` | access granted, counting down to `accessExpiresAt`
|===

`Phase.fromDbString` is total: any unknown string decodes to `Welcome`. The circe instances are `Encoder.encodeString.contramap(toDbString)` and the matching decoder, so `Phase` is a bare JSON string on the wire.

=== IdentificationSurveyType

`Email`, `Profiling`, `Location`, with `email` / `profiling` / `location` as DB strings (`surveys.category`) and the same string-based circe pair. `fromDbString` defaults to `Email`.

=== NextStep and FallbackPhase

Two single-field wrappers around `Phase`, distinguished by intent:

[cols="1,3"]
|===
| Type | Meaning

| `NextStep(phase)`
| the success transition. Emitted by the `Answer*` and `MarkVideoWatched` handlers and serialised to the client as the response body (`application/NextStep.scala`, derived circe pair).

| `FallbackPhase(phase)`
| where a `Provide*` handler sends the guest when the location has no such resource — no next identification survey, no video, no advertiser survey. Never serialised; it is a constructor parameter of the handler.
|===

The concrete values live in `api/src/whitelabel/captal/api/Phases.scala`, as data rather than logic: `nextAfterIdentification = AdvertiserVideo`, `nextAfterVideo = AdvertiserVideoSurvey`, `nextAfterAdvertiserSurvey = Ready`, and the fallbacks `fallbackFromIdentification = AdvertiserVideo`, `unidentifiableFallback = Ready`, `fallbackFromVideo = Ready`, `fallbackFromAdvertiserSurvey = Ready`.

=== Flow and Handler

[source,scala]
----
trait Handler[F[_], C]:          // application/commands/package.scala
  type Result
  def handle(command: C): F[Op[Result]]

trait Flow[F[_], C]:             // application/Flow.scala
  type Result
  def execute(command: C): F[Result]
----

Both carry the result as a type member with an `Aux` alias (`Handler.Aux[F, C, R]`, `Flow.Aux[F, C, R]`), which is how the API names a flow in a `ZLayer` signature. `commands.Op[A]` is the module-wide alias for `CoreOp[Event, Error, A]`.

=== EventHandler

[source,scala]
----
trait EventHandler[F[_], -E]:
  def handle(events: List[E]): F[Unit]
----

Contravariant in the event type, with one extension — `andThen`, sequencing two handlers with `*>`. The server builds its chain from this (see xref:event-sourcing.adoc[Event sourcing]).

=== Application Event and Error

`application/Event.scala` is the sum the handler chain consumes:

[source,scala]
----
enum Event:
  case Survey(event: survey.Event)
  case User(event: user.Event)
  case Video(event: video.Event)
  case Device(event: device.Event)
  case Recovery(event: recovery.Event)
  case Access(event: access.Event)
----

`application/Error.scala` mirrors the aggregates that can refuse, plus three errors that belong to none:

[source,scala]
----
enum Error:
  case NoSurveyAssigned
  case UserNotIdentified
  case TermsNotAccepted
  case NoTermsOfService
  case InvalidEmailFormat(value: String)
  case Survey(errors: NonEmptyChain[survey.Error])
  case User(errors: NonEmptyChain[user.Error])
  case Video(errors: NonEmptyChain[video.Error])
  case Recovery(errors: NonEmptyChain[recovery.Error])
----

=== Handler notes

`AnswerEmailHandler` is the only handler that creates a user and the only one that parses a value itself: a non-`Text` answer, or a `Text` that `user.Email.fromString` rejects, fails with `Error.InvalidEmailFormat` before the survey is even loaded. On success it chains `UserOps.createWithEmail` and then `answerEmail`, so both events come out of one `Op`.

The other three `Answer*` handlers follow one shape: find the user in the state the answer requires (`findAnswering`, or `findAnsweringVideoSurvey` for the advertiser case), then load the survey in the matching state. `None` for the user is `Error.UserNotIdentified`; `None` for the survey is `Error.NoSurveyAssigned`. The answer itself is validated inside `survey.ops`.

`ProvideNextIdentificationSurveyHandler` takes two fallbacks and the difference is load-bearing:

[cols="1,3"]
|===
| Parameter | Chosen when

| `exhausted`
| a user exists and the identification pool has nothing left — the normal end of the phase, emitting `IdentificationCompleted`

| `unidentifiable`
| there is no user *and* no active identification survey, so nobody can be identified; a guest is still created (`NewUserArrived` with no next question) and sent straight to the fallback
|===

`ProvideNextVideoHandler` fails with `Error.UserNotIdentified` when no user has an email: reaching the video phase unidentified is treated as a broken flow, not as a case to serve. With a user and no video, it returns `NextStep(fallback.phase)` and emits nothing.

`MarkVideoWatchedHandler` has two constructors. `withSession` is the one the server uses — it reads `session.currentVideoId`, looks the video up to recover `advertiserId` and `videoType`, and emits `VideoVisualized` plus a `PlaybackEnded` for each playback `VideoRepository.openPlaybacks` reports: watched, the file is no longer being fetched. A missing `currentVideoId` fails with `video.Error.NoVideoAvailable` and an unknown id with `video.Error.VideoNotFound`. The plain `apply` emits no event and returns the next step unchanged.

`StartHandler` and `AcceptTermsHandler` are the only way out of the welcome, and both answer `NextStep(IdentificationQuestion)`: the identification questions hand the guest on themselves when none is left to ask. Where a device stands with the terms is a typestate, as a user's place in the flow is: `Device[S <: State]` (`device/State.scala`), with `State.NotAccepted` — never, or a version that is no longer in force — and `State.Accepted(termsId, acceptedAt)`. `acceptTerms` (`device/ops.scala`) exists only on `Device[State.NotAccepted.type]`, emits `TermsAccepted` and answers the `Accepted` device. `DeviceRepository` finds the session's device in one state or the other (`findAccepted`, `findNotAccepted`), reading it against the version in force; `TermsRepository` answers that version, `TermsVersion(id, number)`, which is the one a device accepts — the page never names one.

`StartPlaybackHandler` emits `PlaybackStarted` only when `fileUrl` is the session's video's current file, and fails with `video.Error.StaleFile` otherwise — the video got a new file after the page was given that one. `EndPlaybackHandler` emits `PlaybackEnded` unconditionally: ending one that already ended, or another session's, is the persistence's no-op, because the page sends it on its way out and cannot wait to be told.

`FinishHandler` grants access, by `AccessGranted`, from either of the two phases that wait for it. From `Ready` the guest went through the flow, so the ready user finishes it as well — `UserFinishedProcess`, carrying what they watched and answered — and with no user it fails with `Error.UserNotIdentified`. From `Recovered` the guest left through an error, possibly before giving an email, so no user is required, and no `UserFinishedProcess` is emitted: the flow was not finished.

`FinishHandler` and `ExpireAccessHandler` are the two ends of one cycle and differ deliberately on the empty case: `FinishHandler` fails when there is nobody to grant access to, while `ExpireAccessHandler` is a silent no-op unless the session is `Authorized` and past its own `accessExpiresAt`. It asks the session, not a user: a session that left through an error before giving an email is authorized with no user, and its access ends all the same. See xref:event-sourcing.adoc[Event sourcing] for what that buys the scheduler.

`RequestRecoveryHandler` takes a `RecoveryCause`: `Server(errorId)`, the id an API error answered with, or `Client(report)`, what the page says it caught. A server error is honoured only when it was recorded with origin `server` against this same session; anything else is `UnknownError`, so an id seen on another guest's screen opens nothing. A client report is always recorded, with its verdict, even when no way out follows. In `Ready`, `Recovered` or `Authorized` both answer `Unrecoverable` with the error's id.

`RedeemRecoveryHandler` refuses an error of another session or one never offered (`UnknownError`), one already taken (`AlreadyRedeemed`), and one taken before its `availableAt` (`NotYet`, carrying the instant). The clock is the command's, so the page's countdown is advisory: it is the server that decides. Its `RecoveryRedeemed` moves the session to `Recovered` and does nothing else: granting access is `finish`'s alone.

== Queries

`application/queries/` declares a `Query[F, Q]` trait (`execute(query: Q): F[Either[Error, Result]]` with the same `Aux` pattern) plus `GetIdentificationSurvey` and an `IdentificationSurveyResponse` enum (`Email`, `Profiling`, `Location`, `Completed`). Nothing outside the package references either: the read side of the portal goes through the repositories and the `Provide*` commands.

== Aggregates

Each aggregate is one package holding `Id`, `Event`, `Error`, a `State`, a case class parameterised by that state, and an `ops` object of extension methods returning `Op`.

=== user

`User[S <: State](id: Id, state: S)` — type-state, so an operation is only in scope for the state it applies to.

[cols="2,2,3"]
|===
| State | Fields | Entered by

| `Guest` | — | `ops.createGuest`
| `WithEmail` | `email` | `ops.createWithEmail`
| `AnsweringQuestion` | `surveyId`, `questionId` | `assignSurvey(Some(q), …)`
| `WatchingVideo` | `videoId` | `assignVideo(…)`
| `AnsweringVideoSurvey` | `advertiserId: Option`, `surveyId`, `questionId` | `assignVideoSurvey(Some(q), …)`
| `Ready` | `redirectUrl`, `watchedVideoId: Option`, `answeredQuestionIds: List` | rebuilt by `UserRepository.findReadyUser()`
| `Authorized` | same three fields | `finish(…)`
|===

`advertiserId` is optional in `AnsweringVideoSurvey` because a promo's survey has no advertiser.

`user/ops.scala`:

|===
| Operation | Receiver state | Emits | Returns

| `createWithEmail(email, now)` | — | `UserCreated` | `User[WithEmail]`

|===

`answerAdvertiserSurvey` narrows the receiver to `User[AnsweringQuestion]` internally, so the answering path is one function regardless of which phase reached it.

`user/Event.scala` carries eight events; see the catalogue in xref:event-sourcing.adoc[Event sourcing]. `user/Error.scala`: `EmailAlreadyRegistered(userId)`, `InvalidEmailFormat(email)`, `SessionExpired(sessionId)`, `NoPendingQuestions(userId)`, `QuestionNotPending(userId, questionId)`.

`user/Id.scala` holds four opaque types over `UUID`/`String`:

* `Id`, `SessionId` — `apply`, `generate`, `fromString`, `unsafe`, with `value` / `asString` extensions;
* `DeviceId` — same; a device is found by its fingerprint (see <<_device,device>>), and its id is generated when it is first seen;
* `Email` — opaque over `String`, validated by `fromString` against the regex `^[A-Za-z0-9+_.-]+@[A-Za-z0-9.-]+$`, with `unsafeFrom` for trusted values.

=== survey and survey/question

`Survey[S <: State](id: Id, state: S)`, with one state per kind of question the repository can hand over:

[cols="2,3"]
|===
| State | Fields

| `WithEmailQuestion` | `question: QuestionToAnswer`
| `WithProfilingQuestion` | `question`
| `WithLocationQuestion` | `question`, `hierarchyLevel: HierarchyLevel`
| `WithAdvertiserQuestion` | `advertiserId: Option[AdvertiserId]`, `question`
|===

Nothing persists `WithAdvertiserQuestion.advertiserId` — `answers` has no advertiser column — it is carried so the emitted event can attribute the answer.

`survey/ops.scala` has one function per category (`answerEmail`, `answerProfiling`, `answerLocation`, `answerAdvertiser`), all the same three steps: `question.ops.validate`, build a `QuestionAnswer(questionId, value, now)`, then `Op.emit(SurveyEvent.QuestionAnswered(surveyId, questionEvent), answer)`. `survey/Event.scala` has a single case, `QuestionAnswered(surveyId, event: question.Event)`, so every survey event wraps a question event.

Ids: `survey.Id` and `survey.AdvertiserId` (opaque over `UUID`), `question.Id` and `question.OptionId` likewise. `FullyQualifiedQuestionId(surveyId, questionId)` is the pair used everywhere a "next question" is named.

==== Question model

[source,scala]
----
final case class QuestionToAnswer(
    id: Id,
    text: LocalizedText,
    description: Option[LocalizedText],
    placeholder: Option[LocalizedText],
    questionType: QuestionType,
    commonRules: List[CommonRule],
    pointsAwarded: Int)
----

`LocalizedText(value, locale)`; `QuestionOption(id, text, displayOrder, parentOptionId)`; `QuestionAnswer(questionId, value: AnswerValue, answeredAt)`.

`AnswerValue`: `SingleChoice(optionId)`, `MultipleChoice(optionIds: Set[OptionId])`, `Text(value)`, `Rating(value: Float)`, `Numeric(value: BigDecimal)`, `DateValue(value: LocalDate)`.

Rules (`question/rules.scala`): `CommonRule.Required`; `SelectionRule.MinSelections|MaxSelections`; `TextRule.MinLength|MaxLength|Pattern|Email|Url`; `RangeRule[A].Min|Max`.

==== Validation

`question/ops.scala` exposes one entry point:

[source,scala]
----
def validate(
    questionId: Id,
    commonRules: List[CommonRule],
    questionType: QuestionType,
    value: AnswerValue): RuleOp[Unit]
----

It runs the common rules and the type-specific rules with `parTupled`, and each rule list with `parTraverse`, so every broken rule is reported, not just the first.

[cols="2,2,3"]
|===
| `QuestionType` | Accepted `AnswerValue` | Checks

| `Radio(options)` | `SingleChoice` | the option id exists → `InvalidOptionSelected`
| `Select(options)` | `SingleChoice` | as above
| `Checkbox(options, rules)` | `MultipleChoice` | every id exists → `InvalidOptionsSelected`; then `MinSelections` / `MaxSelections` → `TooFewSelections` / `TooManySelections`
| `Input(rules)` | `Text` | `MinLength`, `MaxLength`, `Pattern`, `Email`, `Url`
| `Rating(rules)` | `Rating` | `RangeRule[Int]` bounds compared against the `Float`
| `Numeric(rules)` | `Numeric` | `RangeRule[BigDecimal]` bounds
| `Date(rules)` | `DateValue` | `RangeRule[LocalDate]` bounds, via `isBefore` / `isAfter`
|===

Any other pairing fails with `IncompatibleAnswerType(questionId, expected)`. `CommonRule.Required` only rejects a blank `Text` (after `trim`) or an empty `MultipleChoice`; the other answer shapes can never be empty. `TextRule.Email` and `TextRule.Url` carry their own regexes, distinct from `user.Email`'s.

IMPORTANT: the three range errors are constructed with the violated bound in *both* the `min` and `max` fields — `Error.RatingOutOfRange(questionId, min, min, value)` on a lower-bound breach, `(questionId, max, max, value)` on an upper one. Any client rendering both numbers will show the same value twice.

`survey/Error.scala` is the full list the API maps from: `RequiredAnswerMissing`, `InvalidOptionSelected`, `InvalidOptionsSelected`, `TooFewSelections`, `TooManySelections`, `TextTooShort`, `TextTooLong`, `InvalidPattern`, `InvalidEmail`, `InvalidUrl`, `RatingOutOfRange`, `NumericOutOfRange`, `DateOutOfRange`, `IncompatibleAnswerType`, `QuestionAlreadyAnswered`, `QuestionNotFound`, `HierarchyViolation`. The last three are state errors; nothing in `core` emits them today.

==== HierarchyLevel

Location questions are ordered: `State(1)`, `City(2)`, `Municipality(3)`, `Urbanization(4)`. `ordered` lists them, `nextLevel` / `previousLevel` step by `order`, and `canAnswer(toAnswer, lastCompleted)` is true only for `State` when nothing is completed, and otherwise only for the immediate successor.

==== IsoDate

`YYYY-MM-DD` in and out, hand-parsed rather than through `DateTimeFormatter`:

* `parse(text): LocalDate` — splits on the two dashes and throws `DateTimeException` for anything else, including a malformed number component;
* `format(date): String` — `date.toString`.

The only circe instances for `LocalDate` in the codebase are private to `question/codecs.scala` and decode through `IsoDate.parse`.

==== Codecs

`question/codecs.scala` is the browser-facing codec bundle: the four id types as strings, `SelectionRule` / `TextRule` / the three `RangeRule` instantiations (each `@targetName`-annotated, since they erase to one name), `CommonRule` and `HierarchyLevel` as lowercase strings, and derived pairs for `LocalizedText`, `QuestionOption`, `QuestionType`, `QuestionToAnswer` and `AnswerValue`. `AnswerValue` is the one type that travels browser → server, and the same bytes are persisted to `answers.answer_value`.

NOTE: the rule codecs describe the same shape as `question_rules.rule_config`, whose authoritative zio-schema definition is `platform/src/whitelabel/captal/platform/surveySchemas.scala`. The two have to be changed together.

=== device

What the network says about the device a session runs on, and the rule for finding it again.

|===
| Type | Contents

| `Mac` | a MAC as the unsigned 48-bit integer its six bytes spell, most significant first. `Mac.parse` reads twelve hex digits separated by `:`, `-` or nothing, in either case; `show` writes it lower case with colons, as UniFi does
| `Signals` | `clientMac` (a `Mac`, when the redirect carried a readable one) and `fingerprint`, both from the redirect: the MAC is UniFi's, the fingerprint the link shortener's, computed from what the browser reports
| `Matching` | `inline def matches(known, seen)`, implemented by `ByFingerprint`, `ByMac` and `ByMacAndFingerprint`. Inline so a repository can splice it into its query and the database finds the device: Quill reduces it to a `WHERE` at compile time, and it runs as plain Scala everywhere else. It cannot be called through the trait — the compiler refuses to inline it there — only on a concrete policy
| `Policy` | which `Matching` configuration names, `ByMacAndFingerprint` by default: a fingerprint alone is shared by phones of one model and system, and a MAC alone changes when a phone rotates its private address. `covers(seen)` says whether the signals carry what it compares; ones that do not are a new device, since an empty fingerprint would match every other empty one
| `Event` | `DeviceLinked(userId, deviceId, occurredAt)`; `TermsAccepted(deviceId, termsId, occurredAt)`, the device accepting the terms of service in force
|===

A configured policy reaches the query through a `match` where the query is written, one branch per
policy, each compiling its own static query. A `match` inside `core` handing the policy to a lambda
does not compile: the lambda's parameter is typed as the trait, and the concrete policy is lost.

=== recovery

A guest's way out of an error, so that something breaking never leaves them without internet. A
server error the server saw, and it opens at once. A client error only the page saw: nothing in it
can be verified, so it is not judged true or false, it is made to cost time — more than going
through the flow would, unless the guest has shown that they would have.

|===
| Type | Contents

| `ErrorId`, `ErrorFingerprint` | the error's id, which the API answers with and the page asks with; a `Signature`, hashed
| `Origin` | `Server` or `Client`
| `ClientReport` | `bundleVersion`, `name` (`TypeError`, `RangeError`, …), `message` and `frames` (`Frame(file, line, column)`; `fileName` is the file without where it was served from). `signature(published)` is what the error is recognized by
| `Frame.fromStack(stack)` | a stack as the engines print it, read into frames, at most `Frame.MaxFrames` (20): V8's `at name (file:line:column)` lines under the message, SpiderMonkey's and JavaScriptCore's `name@file:line:column`. The engine's own frames, which name no file, are dropped; JavaScriptCore's positionless `global code` is kept at 0:0 so the console markers find it. Used by the client, which compiles `core` to JavaScript
| `Signature` | `bundleVersion`, `name`, and the `fileName`, line and column of the report's first frame in the bundle's own files — without a manifest, its first frame not from the console
| `Manifest` | the bundle a location serves: its version and each file's line lengths. `owns(frame)` says a frame names one of its files; `holds(frame)` that the line and column exist in it
| `Verdict` | `Fabricated(reasons)` or `Plausible(recurrent)`, from `Verdict.of(report, published, otherDevices)`
| `Activity` | what the user did on this device, by kind of effort: `videosWatched`, `videoAnswers`, `identificationAnswers` (profiling and location), `emailAnswers`
| `Progress` | how far this visit got: `Started` (welcome or identification question), `Identified` (at the video), `Watched` (at its survey); `Progress.of(phase)`, and `isFinal` for the phases with no way out
| `Evidence` | what the wait is computed from: activity, progress, recent recoveries, verdict
| `WaitPolicy` | the wait itself, and `recurring`, the shortening of one found recurrent later; `WaitPolicy.Default` is the one a location follows for whatever it did not set (see xref:platform.adoc#location-recovery[`LocationRecovery`])
| `ErrorRecord` | an error as stored: `origin`, its session, `recordedAt`, a client error's `fingerprint` and `verdict`, `availableAt`, `redeemedAt`
| `Event` | `ErrorRecorded`, `RecoveryOffered`, `RecoveryShortened`, `RecoveryRedeemed`
| `Error` | `UnknownError(errorId)`, `AlreadyRedeemed(errorId)`, `NotYet(availableAt)`
|===

A report is `Fabricated` when it contradicts what the server knows, for any of three `Reason`s:

* `ConsoleOrigin` — a frame names no file but the console, `eval` or a bookmarklet
  (`Frame.ConsoleMarkers`, one per engine);
* `UnknownVersion` — the bundle version is not the one the location serves;
* `OutsideTheBundle` — a frame names one of the bundle's files at a line or column it does not have.

Frames of other files — an extension, the browser itself — are not judged. Without a manifest
(none published, or unreadable) only the console check runs: a deployment that failed to publish
one must not count against every guest. A report is `Plausible(recurrent = true)` when at least
`Verdict.RecurrenceThreshold` (1) other device reported the same signature within the policy's
`recurrenceWindow`. One is enough because a device is the redirect's MAC and the link shortener's
fingerprint, not something a guest can mint.

An error can become recurrent after it was offered: an error introduced by a deploy reaches one
guest first, with nothing to tell it from an invented one. So the waiting page asks
(`CheckRecoveryCommand`), and once another device reports the same signature the wait shortens to
`WaitPolicy.recurring` of itself — `recurrentFactor` of the wait it was offered, still counted from
when the error happened, never longer — and the page tells the guest why. The redeem applies the
same rule, so it does not depend on the page having asked.

The signature is how one error is recognized on other devices, and it leaves out what changes
between them while the error stays the same:

* the message — each engine words the same error its own way (`Cannot read properties of
  undefined (reading 'x')`, `undefined is not an object (evaluating 'a.x')`), and versions of one
  engine reword it. The `name` takes its place: the standard fixes it for every engine;
* the frames past the first of ours, which follow whatever path led there;
* where the file was served from: each location serves its own copy of the bundle.

The column stays: the published bundle is minified to one line per file, so the line alone places
nothing. A report with no frame of the bundle's own has no signature and is never recurrent.

The wait, in seconds, is

----
maximum × (1 + videosWatched)^-videoWeight × (1 + videoAnswers)^-videoAnswerWeight
        × (1 + identificationAnswers)^-identificationWeight × (1 + emailAnswers)^-emailWeight
        × (1 | identifiedFactor | identifiedFactor × watchedFactor)
        × (1 + recentRecoveries)^recoveryExponent
        × (fabricatedFactor | recurrentFactor | 1)
----

capped at `ceiling` and rounded to zero below `zeroBelow`. History has diminishing returns: much
of it brings the wait close to zero, and no single answer counts for much. It is the user's on this
device only, so typing someone else's email borrows nothing, and it weighs kinds of effort apart:
a video most, its survey's answer less, a profiling or location answer less still, and the email
almost nothing — answering it again and again is what clearing cookies looks like, while the count
of identification answers grows with real returning visits. This visit's progress takes the wait to
`identifiedFactor` of it once identified and to `identifiedFactor × watchedFactor` once the video is
watched. `recentRecoveries` are the ways out this device took within `recoveryWindow`, which grows
the wait for whoever leaves through errors repeatedly.

Each location can set any of these for itself with `set_recovery_policy`; what it does not set is
the default below.

[cols="2,1,3"]
|===
| `WaitPolicy.Default` | Value | Meaning

| `maximum` | 5 min | a plausible report at `Welcome` from a device with no history
| `ceiling` | 30 min | no wait exceeds it
| `zeroBelow` | 5 s | a wait shorter than this opens at once
| `videoWeight`, `videoAnswerWeight`, `identificationWeight`, `emailWeight` | 1.0, 0.5, 0.25, 0.05 | one video halves it; the email alone takes 3 %
| `identifiedFactor`, `watchedFactor` | 0.3, 0.5 | with no history: 1:30 at the video, 0:45 at its survey
| `recoveryExponent` | 2 | one recent recovery quadruples it, two multiply it by nine
| `fabricatedFactor`, `recurrentFactor` | 10, 0.1 | a fabricated report waits ten times longer; a recurrent one, a tenth
| `recoveryWindow`, `recurrenceWindow` | 30 days, 7 days |
|===

== i18n

`core/src/whitelabel/captal/core/i18n/` is the source of truth for the portal's translation keys.

`I18n.scala` declares the bundle as nested case classes of `String` — `welcome` (with `steps`, `button`, `authorized`, `terms`), `ready`, `loading`, `error`, `question`, `video` — 44 leaf keys today. `error.unknownAccessPoint` is the message for a guest who came through an access point that is not the location's, which nothing the guest does fixes; like every key, each location has to translate it. Each nested type carries babel `Decoder`/`Encoder` instances; the circe pair for the whole tree is in xref:messages.adoc[Messages].

`I18n.descriptions` is an `I18n` value whose leaves hold a description of each key instead of a translation. It is total by construction: adding a field to `I18n` fails to compile until it is described there.

`I18nSchema.scala` derives the flat key set from the type:

[cols="2,3"]
|===
| Member | Meaning

| `keys[A]` | every key `A` requires, as dotted paths in declaration order (`welcome.steps.step1`, …)
| `missing[A](messages)` | which of those keys a given map does not cover
| `decode[A](messages)` | rebuild the value from a flat `Map[String, String]`
| `flatten[A](value)` | the inverse — key → leaf
|===

Derivation walks `Mirror.ProductOf` labels and element types in lockstep with `inline` recursion, through a named `Derived[A]` carrier; `I18n.schema` is the one binding that materialises it, so callers summon the instance instead of re-expanding the fold. The `String` instance is the leaf: a key absent from the map decodes to the literal `[key]`, which renders visibly in the portal rather than failing.

At runtime `platform.services.LocaleServiceQuill.getI18n(locale)` reads `localized_texts` rows with `category = 'frontend'` for the request's `location_id`, maps `entity_id → value`, and hands the map to `I18nSchema.decode[I18n]`. So the i18n key set is the contract between this type and that table; see xref:database.adoc[Database].
