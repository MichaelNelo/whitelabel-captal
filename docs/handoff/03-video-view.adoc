= 03 — AdvertiserVideoView y preload del `<video>`
:toc:

== Estructura actual (`views/AdvertiserVideoView.scala`)

`render` monta 3 cosas en paralelo dentro de un div wrapper:

. Observer que sincroniza `canPlay` + `minTimeReached` → `showIntro=false`
  cuando ambos son `true`. Bindea con `-->` a un `Observer` (es un
  `Modifier`, se subscribe al owner del elemento).
. `child <-- videoData.signal.map` — cuando `videoData=Some(v)`, monta
  `renderVideoHero(v, ...)`. Aquí vive el `<video>` element, *una sola vez*.
. `child <-- showIntro.signal.map` — cuando `true`, monta `renderIntroCard`
  como overlay encima del player.

*Clave*: el `<video>` y el intro overlay coexisten (ambos montados
simultáneamente cuando `videoData=Some && showIntro=true`). El intro tapa
visualmente al player mientras preload sucede debajo.

=== `renderVideoContent` — video Laminar-managed

```scala
videoTag(
  cls              := "video-hero-video",
  src              := video.videoUrl,
  htmlAttr("playsinline", StringAsIsCodec) := "",
  onMountCallback { ctx =>
    val v = ctx.thisNode.ref
    videoRef.set(Some(v))
    v.muted   = true
    v.preload = "auto"
    v.addEventListener("play",           _ => isPlaying.set(true))
    v.addEventListener("pause",          _ => isPlaying.set(false))
    v.addEventListener("ended",          _ => { videoCompleted.set(true); isPlaying.set(false) })
    v.addEventListener("canplaythrough", _ => canPlay.set(true))
    v.addEventListener("error",          _ => ErrorHandler.escalateMessage(...))
    v.play()
  }
)
```

Todo se setea en el `onMountCallback` — el `<video>` element es owned por
Laminar, nunca hay `appendChild` imperativo entre parents.

=== `loadNextVideo` — solo fetch API

```scala
private def loadNextVideo(videoData: Var[Option[NextVideo]], showIntro: Var[Boolean]): Unit =
  Runtime.run:
    VideoApi.getNextVideo().map:
      case Right(VideoResponse.Video(data))   => videoData.set(Some(data))
      case Right(VideoResponse.Step(nextStep)) => Router.syncWithPhase(nextStep.phase)
      case Left(err)                          => showIntro.set(false); ErrorHandler.escalate(err)
```

Ya no crea el `videoEl` imperativamente ni maneja timing del intro.

=== Timing del intro

`IntroTimeoutMs = 3000` — mínimo tiempo visible del intro.

* `canPlay` — se setea desde el listener `canplaythrough` del `<video>`.
* `minTimeReached` — se setea desde `js.timers.setTimeout(IntroTimeoutMs.millis)`
  en `onMount` del render.
* Cuando *ambos* son true, el observer dispara `showIntro.set(false)` →
  intro overlay desmonta → video visible.

Barra visual (`.video-intro-pulse`)::
  Siempre indeterminada (`introSweep` loop). Se decidió que un progress
  bar determinado de 3s comunicaba un tiempo falso.

== Bug histórico: 2 requests + blink

*Antes*: `loadNextVideo` creaba `videoEl = document.createElement("video")`,
seteaba `src`, `videoRef.set(Some(videoEl))`. Después, en el mount del
`.video-hero-video-wrapper`, se hacía `ctx.thisNode.ref.appendChild(videoEl)`.

Firefox (y algunos otros browsers) *reinicia network activity* cuando un
`<video>` element se re-attach a un parent distinto. Resultado:

* Request 1: al setear `src` + `.load()` fuera del DOM
* Request 2: al `appendChild` al DOM (Firefox re-fetch para verify + seek)
* Blink visual: el player aparece brevemente vacío mientras el 2do fetch resuelve

Fix (el actual): el `<video>` vive dentro de `renderVideoHero(v, ...)` que
Laminar monta cuando `videoData=Some`. *Un mount, un request*. El intro es
overlay encima, no wrapper que después swap.

== Descartados

Fetch → Blob → `URL.createObjectURL(blob)`::
  Un solo request pero acumula todo el video en memoria antes de
  reproducir. Rechazado por el user por ineficiente.

MediaSource Extensions (MSE)::
  Streaming chunk-by-chunk al `<video>` element. Bien para videos grandes
  o HLS/DASH. Sobrekill acá — el approach Laminar-managed alcanzó.
  fs2 no está disponible en Scala.js; se implementaría con
  `dom.ReadableStream` + `SourceBuffer.appendBuffer`.

Servir videos desde el server ZIO en vez de LocalStack::
  Descartado, el user prefiere mantener LocalStack para simular producción S3.
