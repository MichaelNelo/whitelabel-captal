= core

The rules of the guest journey, independent of where they run. Which question comes next, what
counts as a valid answer, when a video counts as watched, when access is granted and when it
expires.

The same rules run in the browser and on the server, so the two cannot disagree about whether an
answer is acceptable — the portal can reject a bad answer before sending it, and the server rejects
it again without trusting that the portal did.

== The use cases

Eleven of them. Five answer something, three decide what to serve next, and three close the journey.

[cols="2,3"]
|===
| Command | What it does

| `AnswerEmail`
| Takes the guest's email. Creates the guest if this address is new, recognises them if it is not.

| `AnswerProfiling`
| Takes an answer to a profiling question — age bracket, interests, whatever the venue asked.

| `AnswerLocation`
| Takes an answer to a location question. These carry a hierarchy tag (country, region, city), which
  the model records but does not enforce an order on.

| `AnswerAdvertiser`
| Takes an answer to the advertiser's question, the one that follows the video.

| `MarkVideoWatched`
| Records that a video was played to the end.

| `ProvideNextIdentificationSurvey`
| Picks the next identification question, or reports that there is nothing left to ask.

| `ProvideNextVideo`
| Picks what to play: an advertiser's video or a venue promo.

| `ProvideNextAdvertiserSurvey`
| Picks the question that follows what was just watched, if it has one still unanswered.

| `Finish`
| Ends the journey and grants access. This is what sends the guest to the gateway.

| `ExpireAccess`
| Closes the cycle `Finish` opened, when the granted access reaches its expiry.
|===

== What each one requires first

A command that cannot run says why, rather than doing nothing. These are the preconditions:

[cols="2,3"]
|===
| Refusal | What it means

| `UserNotIdentified`
| The session has no guest attached yet. Everything after the email question requires one, so
  `AnswerProfiling`, `AnswerLocation`, `AnswerAdvertiser`, `ProvideNextVideo` and `Finish` all check
  it.

| `NoSurveyAssigned`
| There is no survey for this location to draw a question from. Every answering command checks it:
  without a survey there is nothing the answer could belong to.

| `InvalidEmailFormat`
| The address does not parse. Checked before anything is written, so a bad address creates no guest.

| `EmailAlreadyRegistered`
| This address already belongs to a guest — the signal to recognise them rather than create another.

| `NoPendingQuestions`
| Nothing is left to ask this guest. Not a failure: it is how the identification phase ends.

| `QuestionNotPending`
| An answer arrived for a question this guest was not being asked. Rejected, because accepting it
  would record an answer nobody asked for.

| `NoVideoAvailable` / `VideoNotFound`
| The location has nothing in rotation, or the video named does not exist.
|===

Answer validation itself lives with the question: each of the seven question types — radio,
checkbox, select, free input, rating, numeric and date — carries its own rules, so a rating outside
its range or a date outside its window is refused by the question, not by the command.

Failures from the three aggregates — guest, survey, video — are wrapped rather than flattened, so a
caller can tell *which* part refused and get every reason it gave, not just the first.

== Where each one sends the guest

A command does not return "ok". It returns the phase the guest belongs in next, and that is what
moves them through the journey:

....
Welcome
  → IdentificationQuestion     while questions remain for this guest
  → AdvertiserVideo            once nothing is left to ask
  → AdvertiserVideoSurvey      if the video just watched has an unanswered question
  → AdvertiserQuestion         otherwise, a general advertiser question
  → Ready                      the journey is done; the gateway is being called
  → Authorized                 the gateway confirmed; the guest is online
  → Welcome                    the access expired and the cycle restarts
....

Because the next phase is the command's answer rather than something the portal decides, a guest who
reloads, comes back later, or arrives on another device lands where their answers say they should —
not where the page they had open thought they were.
